Справочник публичного API библиотеки `escontroller`.

Документ описывает текущую реализацию проекта и предназначен для разработчика. Должен обновляться вместе с изменениями публичного API.

# Core

Пространство имён: `Core`.

## `CoreController`

`CoreController` — основной компонент ядра персонажа (`MonoBehaviour`). Предоставляет общие данные и интерфейсы, которыми могут пользоваться подключаемые модули.

Ядро не должно зависеть от конкретного набора модулей. Модули обращаются к предоставляемому API, не требуя от `CoreController` знания об их внутренней реализации.

### Rigidbody

```
public Rigidbody CoreRigidbody => rigidbody;
```

Возвращает ссылку на `Rigidbody`, используемый персонажем.

- Ссылка назначается через Inspector.
    
- Если ссылка не назначена, `CoreController` пытается получить компонент `Rigidbody` на том же GameObject во время `Initialize()`.
    
- Если компонент не найден, в Console выводится ошибка.

### Check Ground

Система определения нахождения персонажа на земле.

#### `IsGrounded`

```
public bool IsGrounded { get; private set; }
```

Свойство, возвращающее текущее состояние нахождения персонажа на земле.

- `true` — персонаж находится на земле.
    
- `false` — персонаж не находится на земле.
    

Значение обновляется автоматически каждый кадр через `Update()` и метод `CheckGround()`.

Изменять значение извне нельзя.

#### Параметры проверки

|Поле|Описание|
|---|---|
|`groundCheckRadius`|Радиус сферы проверки.|
|`groundCheckVerticalOffset`|Дополнительное вертикальное смещение точки проверки.|
|`_groundCheckMask`|Маска слоёв, участвующих в проверке.|

`_groundCheckMask` автоматически инициализируется в `Initialize()`.

По умолчанию проверка исключает слой `Player` и учитывает остальные слои.

#### Принцип работы

Проверка выполняется методом `Physics.CheckSphere()`.

Центр сферы рассчитывается относительно позиции `Rigidbody`:

```
var origin = CoreRigidbody.position
    + (Vector3.up * groundCheckRadius)
    + (Vector3.up * groundCheckVerticalOffset);
```

Проверка игнорирует триггеры (`QueryTriggerInteraction.Ignore`).

Важно: корректность определения земли зависит от настройки `groundCheckRadius`, `groundCheckVerticalOffset` и расположения коллайдеров персонажа и окружения.

### Action Permission System

Система разрешений определяет, может ли персонаж выполнять конкретное действие. Поддерживает несколько независимых блокировок одного действия.

#### `CanPerform`

```
public bool CanPerform(ActionId action)
```

Возвращает `true`, если для переданного действия нет активных блокировок. Если хотя бы одна блокировка существует, возвращает `false`.

#### `SetCanPerform`

```
public void SetCanPerform(ActionId action, string blockerId, bool canPerform)
```

Добавляет или снимает блокировку действия.

|Параметр|Описание|
|---|---|
|`action`|Идентификатор действия, доступность которого изменяется.|
|`blockerId`|Идентификатор источника блокировки.|
|`canPerform`|`false` — добавить блокировку; `true` — снять блокировку с указанным `blockerId`.|

**Принцип работы:**

- Каждое действие имеет собственный набор блокировок.
    
- Несколько систем могут независимо блокировать одно действие.
    
- Снятие одной блокировки не снимает блокировки, установленные другими системами.
    
- Действие становится доступным, когда его набор блокировок пуст.
    
- Один и тот же `blockerId` не создаёт дубликаты, поскольку блокировки хранятся в `HashSet<string>`.
    

`blockerId` должен быть стабильным идентификатором источника блокировки. Система, которая установила блокировку, должна снять именно свою блокировку, передав тот же `blockerId` и `canPerform = true`.

Пример:

```
core.SetCanPerform(MovementActions.Run, "Stamina", false);
core.SetCanPerform(MovementActions.Run, "Injury", false);

// Снимается только блокировка Stamina.
// Run всё ещё недоступен из-за Injury.
core.SetCanPerform(MovementActions.Run, "Stamina", true);

bool canRun = core.CanPerform(MovementActions.Run); // false
```

Важно: система только хранит состояние разрешений. Она сама не останавливает уже выполняющееся действие и не управляет логикой движения. Модули и контроллеры, выполняющие действие, должны самостоятельно проверять `CanPerform()` в нужных местах.

# Action Contracts

## `ActionId`

```
public readonly struct ActionId : IEquatable<ActionId>
```

Типизированный идентификатор действия. Используется вместо строк непосредственно в API системы разрешений.

```
public string Value { get; }
public ActionId(string value)
```

`Value` содержит строковое значение идентификатора. Конструктор выбрасывает `ArgumentException`, если передана `null` или пустая строка.

`ActionId` поддерживает сравнение через `Equals`, `==` и `!=`, а также корректную работу в коллекциях на основе хеширования.

## `ActionContracts`

Файл `ActionContracts.cs` содержит общедоступные контракты (каталог идентификаторов) действий. Сейчас в нём определён класс `MovementActions`.

### `MovementActions`

Статический класс с идентификаторами действий перемещения:

|Поле|Значение идентификатора|
|---|---|
|`MovementActions.Move`|`Movement.Move`|
|`MovementActions.Run`|`Movement.Run`|
|`MovementActions.Jump`|`Movement.Jump`|

Пример использования:

```
core.SetCanPerform(MovementActions.Jump, "Stamina", false);

if (core.CanPerform(MovementActions.Jump))
{
    // Выполнить логику прыжка.
}
```

При добавлении нового действия следует объявлять его идентификатор в соответствующем контракте, а не создавать произвольные строки в разных модулях.

# Текущее состояние реализации

На данный момент `CoreController` содержит следующие основные системы:

- Получение и предоставление ссылки на `Rigidbody`.
    
- Автоматическое определение нахождения персонажа на земле через `CheckGround`.
    
- Универсальную систему разрешений и блокировок действий.
    

Параметры Ground Check и Rigidbody должны быть корректно настроены в Inspector для стабильной работы ядра.
